## 衣柜商品导入（淘宝联盟）技术方案调研

需求：试穿小程序里，用户粘贴淘宝联盟分享链接/淘口令 → 解析商品信息（含图片）→ 导入自己的衣柜。

确定的技术路线（合规优先）：
1. 唯一合规渠道是淘宝联盟（阿里妈妈）官方 API，禁止爬 item.taobao.com 详情页或逆向 mtop。
2. 文案 → itemId 三路兜底：
   - 含 http(s) 短链（e.tb.cn / s.click / m.tb.cn）→ 后端关闭自动重定向、循环跟随 302，从最终 URL 取 `id` 参数；
   - 含淘口令（¥xxx¥ 或 `?tk=`）→ `taobao.tbk.tpwd.convert`（支持传整段文案）；
   - uland.taobao.com/coupon/edetail → 取 `itemId` 参数，或走活动券接口。
3. 商品详情：`taobao.tbk.item.info.get`（num_iids 最多 40 个，platform=2 无线），返回 title / pict_url / small_images / zk_final_price / item_url / shop_title。
4. 拿佣金必须转链：解析他人口令只拿到原链，需用 `taobao.tbk.privilege.get` 或 tpwd.create 换成自有 PID 的推广链接。
5. 图片：`pict_url` 形如 img.alicdn.com/imgextra/...，尺寸后缀 `_430x430q90.jpg` 是拼接的，去掉即原图。
   小程序无法直接展示阿里域名（downloadFile 白名单 + 需备案），必须后端下载 → 压缩 → 转存自有 OSS/CDN，返回自家 https 域名。
   复用 material-service 已有 OssConfig/OssProperties。
6. 落库建议 wardrobe-service，表 wardrobe_item，唯一键 (user_id, item_id)，按 item_id 缓存（建议 Redis 24h，联盟规范对价格/券信息有时效要求）。

合规红线（已提醒用户）：
- 淘宝联盟规范明确：未经审批不得用 API 数据做 AI 大模型训练（试穿场景特别要注意）。
- 商品图版权归商家，仅可作导购展示，不得去水印/二次分发。
- 基础 API 可申请；链接 API / 三方 API 为邀请制（月日均点击 5 万或成交 10 万等门槛），早期拿不到，用短链跟随兜底。
- 微信内不能直接跳淘宝，只能复制淘口令引导用户去淘宝 App。

环境备注：本次尝试用 curl/PowerShell 实测短链重定向失败，当前沙箱无外网，需用户在本地验证。

## 补充：解析/转链类接口的权限现状（用户实测 tpwd.convert 申请不到）

- `taobao.tbk.tpwd.convert` 属权限包「淘宝客【推广者】淘口令解析&转链」，该包**不会默认开放**（2019 权限包拆分公告已标注），需单独申请/邀请制；解析会暴露他人 origin_pid，联盟一直在收紧。
- `taobao.tbk.item.click.extract`（公用·链接解析出商品 id）在 open.taobao.com 已标【废弃】。
- 联盟正在把解析转链能力收口到**服务商体系**：`taobao.tbk.sc.general.link.convert`（万能转链），`sc.tpwd.convert` / `privilege.get` / `spread.get` 等标"待迁移"。
- 服务商路径门槛：企业主体（营业执照，经营范围含技术服务）、团队与业务模式备案、数据安全承诺、试用期考核（不达标收回 appkey 全部权限）。公司自用型只能自己用，不能对外提供服务。
- 结论（本项目采用）：**不依赖任何解析接口**，走「短链跟随 302 → itemId → item.info.get（基础包）→ 图片转存」；分享侧可用 `taobao.tbk.tpwd.create`（公用包，需后台确认）。纯淘口令（无链接）场景做降级提示。

## 动手改了 wardrobe-service（用户已有完整代码，我做的是定点修复）

现状：用户已写好 WardrobeApplication / Controller / Service / Mapper / Product+WardrobeItem 两表 SQL，配置已填 appKey。

改动清单（只改影响"拿到商品图片"的硬伤）：
1. `TaobaoServiceImpl`：删除 `fields` 参数（tbk.item.info.get 不支持，会被判 invalid-parameter）；`platform` 1→2（无线端）；类目字段改为 `cat_name` 优先、兼容 `cat_leaf_name`。
2. 新增 `TaobaoImageUtil`：URL 归一化（// 补 https、http 升 https、剥阿里 CDN 尺寸后缀）+ 带 UA 下载 + 5MB 限制 + 文件头校验。
   **踩过的坑**：不能从第一个 `_` 一刀切（商品图文件名本身带下划线如 `O1CN01abc_!!123.jpg`），也不能把后缀替换成 `.$1`（`xxx.jpg_.webp` 会变成 `xxx.jpg.webp`）。正确做法是两条正则分别吃「尺寸型 `_430x430q90.jpg`」和「格式型 `_.webp`」，替换为空字符串，最多循环两轮。
3. `WardrobeServiceImpl`：主图下载失败改为抛异常（试穿依赖主图），详情图最多转存 5 张（可配 `taobao.tbk.max-detail-images`）。
4. `TaobaoShareParser`：删掉 11 位长数字兜底（会误判）；Location 支持相对路径解析。
5. 新增开关 `taobao.tbk.tpwd-parse-enabled`（默认 false）—— 该接口属邀请制权限包，没开通就别调，白耗日调用量。

验证：`BUILD SUCCESS`（20 源文件）；图片归一化逻辑用单文件 java 跑过 7 个用例全通过。

### 待提醒用户的关键点
`tbk.item.info.get` 只能查到**已参加淘宝客推广**的商品，随便找的商品可能返回空 results —— 测试要去联盟选品库挑商品。
`taobao.tbk.tpwd.create` 与"解析商品/获取图片"**毫无关系**：它是把自有推广链接生成 ¥口令¥ 供分享用。
"粘贴链接 → 导入衣柜 → 拿到图片"只需要两样：① 自写的短链 302 跟随（0 权限）② `taobao.tbk.item.info.get`（基础包，连 adzone_id 都不需要）。
图片就在 info.get 的返回字段里：`pict_url`（主图）、`small_images`（图集），不需要任何额外接口。
项目落地顺序：申请 info.get → 拿 app_key/secret → 本地 main 跑通签名调用 → 再接进 Spring。
