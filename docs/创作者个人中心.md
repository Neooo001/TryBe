# 创作者个人中心（creator-service）

> 范围：仅「创作者个人中心」——公开主页资料的查看与编辑、账号资料的只读展示。
> 不涉及作品、粉丝、互动等其他模块。

## 1. 设计要点

| 关注点 | 结论 |
|---|---|
| 创作者身份 | `web_user.id`（web 域），与小程序 `wx_user` **零关联**；身份一律取自 `UserContext.requireUser()`，请求参数/请求体均不接受 `creatorId` |
| 数据归属 | 资料行按 `creator_profile.uk_creator` 唯一键定位当前创作者，不存在「读他人资料」的入参面 |
| 域隔离 | 网关 `realm-paths` 已约束 `/creator/**` 必须 web 域令牌（408 跨域拒绝），与 `ItemController` 同一约定 |
| 图片存储 | 只存 OSS **objectKey**，URL 现算不落库；头像 / 封面所在桶为**公共读**，下发**永久 URL**（无签名、不过期）；其余私有桶仍走 `OssService.generatePresignedUrl()` 预签名 |
| 破缓存 | 换图是「同 key 覆盖」，URL 恒定会被浏览器缓存住，故永久 URL 一律追加 `?v={版本号}`；版本号取 `update_time`（确认接口取当前时间戳） |
| 存储桶 | 头像 / 封面存**第二 bucket** `trybe-avatar`（`aliyun.oss.bucket-name2`，公共读），与物品图/模特图所在默认桶 `trybe`（私有）物理隔离；未配置第二桶时自动回落默认桶 |
| URL 形态 | 统一由 `OssService.accessUrl(bucket, key)` 判定：公共读桶 → `getFileUrl()` 永久 URL；私有桶 → 预签名 URL。桶权限变更只改配置，业务代码不动 |
| 上传链路 | 复用现有 P1 预签名 / P2 确认直传（`UploadController`），仅新增 `AVATAR` / `COVER` 两个场景；永久 AK/SK 不进前端 |
| 账号资料 | `WebUserBrief` 对 `web_user` 做**只读投影**（刻意不映射 `password_hash`），手机号服务端脱敏后返回；creator-service 对 `web_user` 无任何写操作 |

## 2. 数据模型

```
creator_profile（新增，与 web_user 1:1，首访懒创建）
  creator_id      BIGINT    创作者用户ID（web_user.id）
  nickname        VARCHAR(32)  创作者昵称（公开主页展示名）
  avatar_key      VARCHAR(255) 头像 OSS objectKey（NULL=默认头像）
  cover_key       VARCHAR(255) 主页封面图 OSS objectKey（NULL=默认封面）
  bio             VARCHAR(512) 个人简介
  field_codes     VARCHAR(255) 创作方向，逗号分隔 CreatorField（最多 5 个）
  homepage_status VARCHAR(16)  ENABLED 启用 / DISABLED 停用（**仅管理端可改**）

web_user（已有，只读，不落本模块）
  phone / nickname / create_time / last_login_time
```

迁移脚本：`sql/creatorService/创建创作者主页档案表.sql`（幂等，含存量创作者回填与校验 SQL）。

创作方向字典由后端枚举 `CreatorField` 维护（发色 / 穿搭 / 美甲 / 美妆 / 配饰 / 鞋包），
随 `GET /creator/profile` 的 `fieldOptions` 下发，**前端不得硬编码选项**；
上限 `fieldMax` 一并下发，避免同一约束两处维护。

## 3. 接口

### PF1 获取当前创作者个人中心资料

```
GET /creator/profile
Authorization: Bearer {web 域 accessToken}
```

响应 `data`：

```json
{
  "creatorId": 1001,
  "nickname": "林小满",
  "avatarKey": "creator/1001/profile/avatar.png",
  "avatarUrl": "https://trybe-avatar.oss-cn-qingdao.aliyuncs.com/creator/1001/profile/avatar.png",
  "coverKey": null,
  "coverUrl": null,
  "bio": "身高 165 / 微胖梨形，只推自己真正试过的版型。",
  "fieldCodes": ["HAIR_COLOR", "OUTFIT"],
  "homepageStatus": "ENABLED",
  "account": {
    "phoneMasked": "138****8000",
    "nickname": "小Try",
    "createTime": "2026-09-01T10:22:31",
    "lastLoginTime": "2026-09-27T09:10:02"
  },
  "fieldOptions": [
    { "code": "HAIR_COLOR", "name": "发色" },
    { "code": "OUTFIT", "name": "穿搭" }
  ],
  "fieldMax": 5
}
```

- `avatarUrl` / `coverUrl` 为空表示未设置，前端渲染默认占位图。
- 档案行不存在时**懒创建**默认行（昵称取注册昵称，`homepageStatus=ENABLED`）。
- 账号行缺失（注销/归档）→ `402 数据不存在·账号不存在或已注销`。

### PF2 更新当前创作者个人中心资料

```
PUT /creator/profile
{ "nickname": "林小满", "avatarKey": "creator/1001/profile/avatar.png",
  "coverKey": "", "bio": "…", "fieldCodes": ["HAIR_COLOR", "OUTFIT"] }
```

**白名单字段**（其余字段 DTO 无绑定，提交即忽略）：

| 字段 | 是否必填 | 语义 | 校验 |
|---|---|---|---|
| `nickname` | 是 | 公开主页昵称 | `@NotBlank` + `@Size(32)`，服务端再 trim 兜底（防全空格绕过） |
| `bio` | 否 | 个人简介 | `null`=不修改，`""`=清空，≤512 字符 |
| `avatarKey` | 否 | 头像 objectKey | `null`=不修改，`""`=恢复默认；非空必须精确命中 `creator/{uid}/profile/avatar.{ext}` |
| `coverKey` | 否 | 封面 objectKey | 同上，归档位为 `creator/{uid}/profile/cover.{ext}` |
| `fieldCodes` | 否 | 创作方向 | `null`=不修改，`[]`=清空；逐个严格解析、去重、上限 5（非法编码 → 100） |

**不接受修改**：`creatorId`、身份/审核/统计字段、`homepageStatus`（主页展示状态仅平台管理端可改，创作者接口只读）、
手机号/账号昵称/密码（走 user-service 专有接口）。

### 头像 / 封面上传（复用现有直传流程）

```
POST /creator/uploads/presign   { "scene": "AVATAR", "ext": "png" }   # 或 "COVER"
  → { objectKey, uploadUrl, expireSeconds }        # tmp 位，10 分钟有效
PUT {uploadUrl}                                    # 浏览器直传 OSS，Content-Type 须与签名一致
POST /creator/uploads/confirm   { "scene": "AVATAR", "objectKey": "…" }
  → { objectKey, accessUrl, width, height }        # 归档到 profile 目录
```

> ⚠️ P1 的 `uploadUrl` **仍然是预签名 URL，且必须保留**：
> 「公共读」只放开匿名**读**权限，写入（PUT）依旧需要签名授权，
> 否则等于把桶开放成任何人可写。

**存储桶**：`AVATAR` / `COVER` 两个场景的 P1 预签名、P2 读校验、P2 归档、访问 URL 现算
**全部使用第二 bucket**（`aliyun.oss.bucket-name2`，即 `trybe-avatar`）；
其余场景（`ITEM_*` / `MODEL_IMAGE`）继续走默认 bucket（`trybe`）。
bucket 由 `UploadScene.isProfileImageScene()` 统一判定，
避免「写 A 桶、读 B 桶」造成对象读不到的隐蔽故障。

**URL 形态**：`trybe-avatar` 是**公共读**桶，因此 `confirm` 返回的 `accessUrl` 与
`GET /creator/profile` 返回的 `avatarUrl` / `coverUrl` 都是**永久 URL**（形如
`https://trybe-avatar.oss-cn-qingdao.aliyuncs.com/creator/1001/profile/avatar.png`），
不带 `Expires`/`Signature`，不会过期、可被浏览器与 CDN 缓存。
判定逻辑收敛在 `OssService.accessUrl(bucket, key)`：桶被改成私有后，
只要把 `bucket-name2-public-read` 置为 false，就会自动回落到预签名 URL，业务代码无需改动。

**缓存与版本号**（必读，否则会踩「换了头像页面不变」）：

归档位是**覆盖式固定路径**，换图时 objectKey 不变、对象被原地覆盖 —— 于是 URL 与旧图**完全一致**。
OSS 默认又不返回 `Cache-Control`，浏览器走启发式缓存，结果就是新头像传上去了、页面还是旧图。

解决办法是给永久 URL 追加版本号 `?v={毫秒时间戳}`：

| 出处 | 版本号取值 | 理由 |
|---|---|---|
| `GET/PUT /creator/profile` | `creator_profile.update_time` | 稳定值：内容没变版本号不变（缓存照常命中），换图才变 |
| `POST /creator/uploads/confirm` | 当前时间戳 | 刚上传完必须立即刷新，不能让 `<img>` 命中旧地址 |

实现在 `OssService.accessUrl(bucket, key, version)`：

- **只对公共读桶拼接**。预签名 URL 的 query **参与签名计算**，追加参数必然
  `403 SignatureDoesNotMatch`；好在它自带的 `Expires`/`Signature` 每次都在变，
  天然不会被缓存，不需要版本号 —— 所以私有桶分支直接忽略 version。
- **version 必须是稳定值**。切勿传 `System.currentTimeMillis()` 作为「查询接口」的版本号，
  否则每次请求 URL 都变，浏览器与 CDN 缓存彻底失效，白白放大流量。
- 若日后接入 CDN，需确认 CDN 把完整 URL（含 query）作为缓存键，否则版本号不生效。

归档位（覆盖式，换图即覆盖同路径对象，**bucket 内路径不变**）：

```
creator/{userId}/profile/avatar.{ext}
creator/{userId}/profile/cover.{ext}
```

## 4. 权限与安全规则

1. 未认证 → `UserContext.requireUser()` 抛 `301 未登录`。
2. 资料不存在 → 懒创建；账号不存在 → `402`。
3. 越权读/写他人资料 → 无入参面（`creatorId` 只来自 JWT），资料行按唯一键定位。
4. 越权绑定他人 OSS 对象 → `CreatorOssPathBuilder.isProfileAvatar/isProfileCover` 精确匹配归档位，
   失败抛 `100 头像必须通过个人中心上传接口获取，不可绑定其他图片`。
5. 非图片用途对象（物品图、模特图等）同样被归档位匹配拒绝；扩展名走 `FileTypeUtils` 白名单。
6. 手机号只在服务端脱敏（`138****8000`）后返回，密码哈希永不进入任何 VO。

## 5. 部署注意

1. 先执行 `sql/creatorService/创建创作者主页档案表.sql`，再发布代码（与既有迁移脚本同序）。
2. Nacos 需变更一处：`shared-oss.yaml` 追加三项
   —— `aliyun.oss.bucket-name2: trybe-avatar`、`bucket-name2-public-read: true`
   （可选 `bucket-name2-domain`）；网关路由 `/creator/**` 已存在，无需改。
   详见 `sql/creatorService/Nacos配置步骤.md` 第 5 节。
3. **已入库的存量头像/封面需搬桶**：把 `trybe` 桶内 `creator/*/profile/*` 对象
   按原路径复制到 `trybe-avatar`（objectKey 不变，DB 无需改数据），
   顺序必须是「先加配置 → 再搬对象 → 再发版」。命令见 Nacos 配置步骤文档第 7 节。
4. 把 `trybe-avatar` 的读写权限设为**公共读（私有写）**；
   浏览器直传 PUT 仍需在 **`trybe-avatar`** 桶侧放行 CORS
   （来源 `http://127.0.0.1:5173` 等，方法 `PUT/GET/HEAD`）。这两项都是 OSS 控制台配置，不在代码库内。
5. **已知副作用**：公共读桶内的对象路径是可枚举的（`creator/{id}/profile/avatar.{ext}`），
   头像本就是公开主页内容，可接受；若日后要放敏感图片，请勿放进该桶。
