## 1. 改造后的账号模型（一句话）

小程序与 Web 是**两个完全独立、零交集**的账号域：

| 维度 | wx 域（小程序） | web 域（创作者后台） |
| --- | --- | --- |
| 表 | `wx_user`（原 `user` 改名） | `web_user`（新建） |
| 归档表 | `user_phone_history` / `phone_transfer_log` | `web_user_archive`（沉睡归档） |
| 登录方式 | 微信一键登录；可选「手机号 + 密码」 | **仅**「手机号 + 密码」 |
| 手机号语义 | **可选**，仅为「换设备找回数据」提供方便 | **账号标识**（唯一键） |
| 路径前缀 | `/users/**`、`/wardrobe/**`、`/profiles/**`、`/materials/**` | `/web/**`、`/creator/**` |
| JWT claim | `realm=wx` | `realm=web` |

**关键约束**：`userId` 只在域内唯一（wx#1 ≠ web#1），因此令牌必须携带 `realm`，网关按路径校验，**未命中任何配置的路径一律拒绝（fail-closed）**。

## 3. 上线前必须人工同步的配置（**不在 git 中**）

### 3.1 Nacos：`gateway-routes.json`

新增一条 `/web/** → lb://user-service` 的路由（已发布到 Nacos，上线环境需同样人工确认）：

| id | predicates | uri |
| --- | --- | --- |
| `web-auth-service` | `Path=/web/**` | `lb://user-service` |

快照文件：`sql/gateway/gateway-routes.json`（该文件就是发布到 Nacos 的内容，可直接复制粘贴）。

### 3.2 网关本地 `TryBe-gateway/src/main/resources/application.yml`（.gitignore 中）

```yaml
hm:
  auth:
    excludePaths:
      - /users/login                 # 微信一键登录
      - /users/auth/captcha
      - /users/auth/sms/code         # wx 绑号 / 设置密码发码
      - /users/auth/login/password   # wx 密码登录
      - /web/auth/captcha
      - /web/auth/register
      - /web/auth/login
      - /auth/refresh-token
      - /hi
    realmPaths:
      wx:  [/users/**, /wardrobe/**, /profiles/**, /materials/**]
      web: [/web/**, /creator/**]
      # 跨域共享：登出/刷新只认令牌自身，不做域匹配
      any: [/auth/**]
```

> ⚠️ `any` 这一段**不能省**：`/auth/logout` 需要鉴权但不属于任何单一域，
> 而 `matchRealm` 是 fail-closed（未命中任何模式即拒绝），缺了它会导致**登出接口一律 408**。
> `/auth/refresh-token` 在白名单里，不受影响。

**白名单刻意不放行**（放行即等于免鉴权改数据）：
- `/users/auth/phone/bind`、`/users/auth/phone`（wx，必须登录）
- `/web/auth/password/change`（web，必须登录）

### 3.3 `MvcConfig`（已在代码中同步）

`TryBe-common/.../config/MvcConfig.java` 的 `excludePathPatterns` 与 3.2 的白名单逐条对齐，网关放行、服务内拦截器也必须放行，否则会出现「网关过了、服务内 301」。

## 4. Redis 清理（清库后必须做，否则旧令牌仍能通过校验）

```bash
# 旧刷新令牌 / 设备令牌集合（结构已变：user_tokens:{realm}:{userId}）
redis-cli --scan --pattern 'refresh_token:*' | xargs -r redis-cli DEL
redis-cli --scan --pattern 'user_tokens:*'    | xargs -r redis-cli DEL

# 令牌黑名单（jti）
redis-cli --scan --pattern 'token_blacklist:*' | xargs -r redis-cli DEL

# 图形验证码 / 短信限流（清库后手机号与限流计数都归零，一并清掉最干净）
redis-cli --scan --pattern 'captcha:*'        | xargs -r redis-cli DEL
redis-cli --scan --pattern 'sms:limit:*'      | xargs -r redis-cli DEL
redis-cli --scan --pattern 'sms:day:*'        | xargs -r redis-cli DEL
```

> Windows 无 `xargs` 时，用 `redis-cli KEYS 'refresh_token:*'` 逐个 `DEL`，或直接用 `redis-cli FLUSHDB`（个人开发库，最省事）。

**前端**：`authStore` 的 persist `version` 已升到 **2**，旧的 `trybe:auth`（含 `role` / `phoneState`）会被 zustand 丢弃并重写，用户需重新登录一次。

## 6. 回归清单

### 6.1 web 域（后台 `D:\trybeHtml`）

- [ ] `/register` 能拉到图形验证码（`/web/auth/captcha`）
- [ ] 新手机号注册成功 → 直接进首页，localStorage `trybe:auth` 中 **无** `role`/`phoneState`
- [ ] 同一手机号**再注册**：返回 405「该手机号已被注册」，页面出现「去登录」按钮
- [ ] 把某账号 `last_login_time` 手工改到 200 天前 → 再用该手机号注册：**归档放行**（`web_user_archive` 多一行、原行删除、注册成功）
- [ ] `/login` 手机号不存在 与 密码错误 → 都返回「手机号或密码错误」（防枚举）
- [ ] 登录后访问 `/creator/**` 正常（realm=web 命中）
- [ ] 「账号安全」改密：原密码错误 → 「原密码不正确」；成功 → 跳登录页且旧令牌失效（拿旧 token 调接口返回 40102）
- [ ] 改密**不影响**小程序会话（小程序侧不需要重新登录）

### 6.2 wx 域（小程序）

- [ ] 微信一键登录 → 直接进首页，**不再强制跳绑号页**
- [ ] 「设置 → 绑定手机号」自愿绑号：收到验证码即视为归属，若该号已被别的 wx 账号占用 → **自动把上个账号的手机号置空**（D3 保留），本账号绑定成功
- [ ] 被置空的账号重新登录后 `phoneState=RELEASED`，首页出现软提示横幅（可关闭）
- [ ] `phone-login` 页（手机号 + 密码）登录成功 → 正常跳回「我的」
- [ ] 小程序**没有**短信验证码登录入口（`/users/auth/login/sms` 已删除）

### 6.3 跨域隔离（本轮核心，必须测）

- [ ] 拿**小程序**的 accessToken 调 `/web/auth/password/change` → 网关返回 **408**「无权访问该端接口，请重新登录」，前端清态跳登录
- [ ] 拿**后台**的 accessToken 调 `/users/auth/phone` → 同样 408
- [ ] 网关本地 yml 中删掉 `realmPaths` 任意一项做反向验证：该域请求应被拒（fail-closed 生效）
- [ ] `/auth/refresh-token` 刷新后 realm 不变（wx 令牌刷新不出 web 令牌）
- [ ] 后台点「退出登录」→ `/auth/logout` 返回成功（**不是 408**），令牌进黑名单后再调业务接口返回 40102
- [ ] 小程序登出同样正常（`/auth/logout` 对两个域都放行）

### 6.4 单角色

- [ ] 全仓 `grep -rn "RoleGuard\|ROLE_USER\|ROLE_CREATOR\|creator:role"` 为空
- [ ] creator-service 的 `/creator/stats/admin/**` 等管理员端点已不可访问（404）

## 7. 已知取舍与遗留

| 项 | 决策 | 理由 |
| --- | --- | --- |
| Web 注册无短信验证 | 只靠图形验证码 | 个人毕设，无资质接短信；图形码挡住批量注册 |
| 手机号被占用的兜底 | 沉睡（≥180 天未登录）→ 整行归档后放行；活跃 → 405 | 兼顾「运营商二次放号」与「原主还在用」 |
| D3 归属转移 | **只在 wx 域保留**，web 域不用 | 小程序绑号是「收到验证码即归我」；web 手机号是账号本身，不能转移 |
| 小程序绑号门禁 | 取消硬拦截，改为自愿 | 用户明确要求「不强制」 |
| 刷新令牌隔离 | `user_tokens:{realm}:{userId}` | 否则 `MAX_DEVICE_COUNT=1` 会让 Web 登录把小程序踢下线 |
| `docs/auth-v2/**` | 作废留档 | 描述的是「统一账号体系 v2」（手机号跨端打通），与本设计相反 |

**未实现**：Web 端「找回密码」。当前只能凭原密码改密；忘记密码需手工改库（`web_user.password_hash`，用 BCrypt 生成）。毕设范围外，如需可做「短信验证码重置」但需短信资质。
